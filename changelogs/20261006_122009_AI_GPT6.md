## Human-Readable Summary

Consecutive writable signal reducers accumulate accepted changes without intermediate reads. Three increments
now produce 3 regardless of observation. Computed signals retain separate output/source arguments and lazy
computation; notifications remain coalesced and throttled output waits for its trigger.

## Technical Details

- EventSignal.set selects the latest accepted source for the first reducer argument only when the signal has
  no computation. Computed reducers still receive the last output and latest source separately. This narrow
  change avoids eager get(), accidental dependencies and notification scheduler changes.
- Twelve regression cases cover accumulation, scheduling, primitive/object values, data, undefined, exceptions,
  sync/async computation, mapping, throttle and dependency isolation. New signals use scoped using declarations
  and Symbol.dispose cleanup. The throttle case checks listener removal after leaving the resource scope;
  derived signals are disposed before their sources through reverse declaration order.
- The async case uses a plain inline async computation and no explicit generic arguments. With explicit T=string,
  default R=string rejects Promise<string>; jest.fn was not the cause. computationsCount verifies one initial
  computation, no eager computation during writes, and one subsequent computation. All new signal identifiers
  use the $ suffix; AGENTS.md makes this convention explicit even without loading the optional module skill.
- Strict compile-only fixtures verify constructor inference, exact result types and invalid source writes.
  Automatic inference already works for the simple constructor case. Roadmap task 03.1 schedules the coordinated
  constructor/factory type repair next, with reproductions for async factory calls, contextual self.data and
  differing initial/output types; no library generic declarations were changed as part of this fix.
- The existing clock-throttle test uses three reducers instead of its workaround and expects 12 after aborting
  throttle and applying a literal write plus two increments, replacing expectations that preserved the known bug.
- Roadmap EN/RU status records completion and retains pre-fix integration evidence. Runtime/type-check separation
  remains a separate stage 01 task. Dependency packages and the Junction ORM integration copy are unchanged.
- The remaining emitter-throttle workaround is replaced with two actual reducers. The owner confirms the
  formerly commented computed reducer sequence is required: its +3 workaround is removed and its trigger test
  is explicitly skipped until roadmap task 03.2 implements the required result 4 (currently 2).
  Inactive _setPromise/forced-read sketches are removed, with separate design requirements for ordered computed
  output and async waiting, including throttle, errors, cancellation and cleanup. No queue is implemented here.

## [RU] Технические детали

- EventSignal.set выбирает последнее принятое исходное значение для первого аргумента reducer только у сигнала
  без computation. Computed-reducer по-прежнему получает отдельно последний output и последний source. Узкое
  исправление не добавляет принудительный get(), случайные зависимости и изменения планировщика уведомлений.
- Двенадцать регрессионных случаев охватывают накопление, расписание, примитивы/объекты, data, undefined, исключения,
  sync/async computation, mapping, throttle и изоляцию зависимостей. Новые сигналы используют scoped using
  и очистку через Symbol.dispose. Throttle-тест проверяет удаление слушателя после выхода из области ресурса;
  производные сигналы уничтожаются раньше источников благодаря обратному порядку объявлений.
- Асинхронный случай использует обычную inline async computation без явных generic-аргументов. При явном T=string
  параметр R=string по умолчанию отвергает Promise<string>; причина не в jest.fn. computationsCount проверяет
  одно начальное вычисление, отсутствие принудительного вычисления при записях и одно последующее вычисление.
  Все новые идентификаторы сигналов имеют суффикс $; AGENTS.md явно закрепляет это соглашение без загрузки module skill.
- Строгие compile-only fixtures проверяют вывод типов конструктора, точные типы результата и неверные записи source.
  Автоматический вывод уже работает для простого конструктора. Задача roadmap 03.1 назначает следующим совместное
  исправление типов конструктора/фабрики с воспроизведением async-вызова фабрики, контекстного self.data и разных
  initial/output; generic-декларации библиотеки в рамках этого исправления не изменялись.

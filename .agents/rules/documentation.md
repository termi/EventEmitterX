## Documentation Language Rules

The separate-file translation rules below apply to ordinary project
documentation outside `changelogs/`, subject to the AI instruction exceptions.

For every Markdown file under `changelogs/`, including its subdirectories,
use one bilingual file: English content first, followed by the equivalent
Russian translation at the end of the same file.
Never create a separate `_RU.md` counterpart under `changelogs/`.

The changelog-specific language and commit rules take precedence over
the general documentation rules.

When creating any project documentation file (e.g. `PROJECT_ANALYSIS.md`, `API.md`, `ARCHITECTURE.md`, `README.md`, etc.):

1. **For any Markdown document generated by an AI agent, always start the file with a properties block** (first lines of the file, before any headings/content):
   ```yaml
   ---
   iso date: <ISO date time string>
   timestamp: <Milliseconds since epoch>
   ai_model: <ModelName>
   git user: <git user name + email>      ← in format: `"username" <email>`
   area: <comma-separated list of affected areas, e.g.: frontend, tests, auth, backend>
   ---
   ```

2. **Default language is English** — the primary file must be written in English
3. **For ordinary project documentation outside `changelogs/`, always
   create a Russian version in a separate file** alongside the English
   original, with `_RU` added before the file extension:
   - `PROJECT_ANALYSIS.md` → also create `PROJECT_ANALYSIS_RU.md`
   - `API.md` → also create `API_RU.md`
   - `ARCHITECTURE.md` → also create `ARCHITECTURE_RU.md`
4. Both files must have **equivalent content** — same structure, same sections, same level of detail
5. Commit both files together under the `docs` type in a single commit

### Exception: Agent Skills / AI Instruction Files

Do **NOT** create a `_RU.md` counterpart for markdown files located in folders typically used for AI agent configuration or skills, such as:
- `.github/` (e.g. `copilot-instructions.md`, `CODEOWNERS`)
- `.cursor/`
- `.continue/`
- `.agents/`, root `AGENTS.md`, and other AI-tooling instruction files or directories

These files are technical instructions for AI agents and do not require translation.

### Skill Entrypoint Frontmatter

For a `SKILL.md` entrypoint, use one standard YAML frontmatter block at the start
of the file. Keep `name` and `description` at the top level. Nest all required
document properties (`iso date`, `timestamp`, `ai_model`, `git user`, `area`)
inside `metadata`, alongside any existing skill metadata. Do not add a second
properties block or unsupported top-level keys. Supporting Markdown references
use the normal properties block. This schema exception does not remove the
metadata requirement or create a Russian translation requirement for AI skills.

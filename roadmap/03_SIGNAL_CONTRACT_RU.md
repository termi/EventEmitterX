# Контракт сигнала — реализация и решения

Реализована связанная основная часть roadmap 03.1 и 03.2. Ниже перечислены
решения для проверки владельцем после возвращения. Публикация пакета, выделение
React, автоматическая сборка мусора и расширенная матрица версий TypeScript
остаются отдельными задачами.

## Модель значений и типов

`EventSignal<T, S = Awaited<T>, D = undefined, R = T>` сохраняет четыре
существующие позиции generic. T описывает начальное значение, S — записываемый
source, D — объект данных, R — непосредственный результат computation.
Разрешённый output имеет тип `Awaited<T> | Awaited<R>`. При контекстном выводе
примитивные литералы могут расширяться; именованные callbacks могут сохранять
начальный литерал. Потребителю следует опираться на публичный тип output,
а не на конкретный выведенный начальный литерал.

Конструктор и фабрика выводят типы inline sync, async и hybrid callbacks,
включая `self$.data`, именованные callbacks и Jest mocks на TypeScript 5.9.3:

```ts
using signal$ = EventSignal.createSignal('initial', async (_prev, source, self$) =>
    `value:${source + self$.data.step}`, {
    initialSourceValue: 0, data: { step: 1 },
});
signal$.set((_prev, source, data) => source + data.step);
const value = await signal$.get(); // string
```

Третий аргумент callback с автоматически выведенным типом — полный класс
EventSignal, включая запись, подписки, React-методы и markNextValueAsForced.
Его режим результата консервативно равен начальному домену либо Promise
разрешённого домена и не зависит от результата callback R. Прямая связь
контекстного self с R воспроизводила ошибки рекурсивного вывода; отдельный
режим результата сохраняет автоматический вывод без удаления методов и any.
Созданный сигнал по-прежнему выводит фактический R из callback. Совместимые
перегрузки допускают явно аннотированные callbacks с точным режимом результата self.

Предыдущий read-only Pick исключал методы существующих computations; он
отвергнут после регрессии object-returning примера с markNextValueAsForced.
Compile fixtures теперь проверяют полный тип/API класса, типизированные запись/data,
вывод конструктора и фабрики, no-source и hybrid callbacks, проекции через self
и этот конкретный object-returning пример. Анонимные типы initial/result объектов
могут образовывать структурно эквивалентный union; проверяются типы свойств
и присваивание в обе стороны вместо номинальной идентичности типов.

Выведенный результат должен соответствовать начальному разрешённому домену;
при проверке совместимости примитивные литералы расширяются. Разные домены
начального значения/output требуют явного union, поскольку callback должен
принимать и первое предыдущее значение, и последующие результаты:

```ts
using union$ = new EventSignal<string | number, number, undefined, string>(
    0, (_prev, source) => `value:${source}`, { initialSourceValue: 0 },
);
```

Альтернативы: заменить все четыре позиции generic, оставить результат без
ограничений с неверным типом предыдущего значения или использовать `any`
для self. Они отвергнуты ради сохранения явных потребителей и корректных
входов callback. TypeScript не выводит пропущенные аргументы после явно
указанных generic-аргументов: используйте вывод всего вызова или задавайте
все четыре позиции для явно типизированной асинхронной computation.

## Чтение и проекции

`getLast`, `getSync` и `getSyncSafe` возвращают разрешённый output. Начальный
Promise добавляет `undefined` до первого разрешения. Типы listener и React
snapshot включают ту же возможность; начальный ожидающий Promise не выдаётся
как значение listener.

`get` и `getSafe` описывают синхронный output и Promise домена output.
Для асинхронной строковой computation тип чтения — `string | Promise<string>`:
hybrid computations и writable-сигналы с разрешённым начальным Promise всё ещё
могут возвращать синхронное значение. Native async computations сохраняют
Promise fallback-чтения, включая после уничтожения, через Promise.resolve.
Уже наблюдавшийся Promise result также сохраняет Promise-чтение после уничтожения;
ожидающий начальный Promise возвращает Promise.resolve(getLast()), не ожидая
брошенную начальную работу. Native async functions определяются без выполнения
до уничтожения. `await signal$.get()` работает для обоих путей.
`tryGet` зеркалирует контракт с payload `{ ok, error, result }`. Существующее
чтение при ошибке computation сохраняет последнее значение; ожидающие записи
дополнительно отклоняются при ошибке.

Generic R стирается в runtime. Обычную функцию, возвращающую Promise, невозможно
отличить от синхронной до первого вызова. Поэтому статический тип get остаётся
union; гарантия Promise для каждого вызова требует явного runtime async-контракта,
запланированного на этапе 03. Тесты, требующие настоящий Promise, используют
instanceof guard перед then. Один Jest expect не сужает union TypeScript.
Потребители могут использовать await или Promise.resolve для нормализации чтения,
но тест не должен нормализацией скрывать проверяемое поведение.

Payload Promise включает предыдущий output после undefined/no-update или error
fallback. ReadResult нормализует этот payload вместо выдачи raw computation Promise
type, исключая повторные Promise-ветви и включая undefined для проекций, которые
ещё не опубликовали первый output.

`map` — односторонняя проекция разрешённого output, ожидающая async read,
с начальным `undefined` и source типа `never`. Запись и mutation также
выбрасывают ошибку runtime. Data, методы и React-метаданные не копируются.
Производный сигнал уничтожается отдельно; чтения после await не получают
новой гарантии отслеживания асинхронных зависимостей. Двусторонний mapping —
будущий API.

## Последовательные reducers и публикация

Обычные source-записи остаются ленивыми и сохраняют поведение последней
записи. Writable reducers получают последнее принятое значение. Computed
reducers получают output предыдущих принятых записей, source передаётся
отдельно. Промежуточный output хранится в приватном кеше; он не меняет
опубликованное последнее значение, version и не освобождает throttle.
Реальные промежуточные computations увеличивают `computationsCount`,
финальный расчёт повторно использует ещё актуальный preview. Принятые
изменения source и зависимостей инвалидируют previews через epoch.

```ts
using signal$ = new EventSignal(0, (_prev, source) => source * 10,
    { initialSourceValue: 0 });
signal$.get();
signal$.set(prev => prev + 1); // source 1
signal$.set(prev => prev + 1); // source 11
signal$.set(prev => prev + 1); // source 111
signal$.getLast(); // 0, until normal publication
signal$.get(); // 1110
```

Промежуточный расчёт — осознанное исключение из ленивости, необходимое,
когда reducer использует output. Альтернативы: reducers только по source,
публичный get между записями или сохранение устаревшего output. Они либо
противоречат требуемой последовательности, либо преждевременно публикуют
значения. Активные подписчики сохраняют объединение в microtask;
throttle/trigger управляют публичной публикацией. Побочные эффекты computation
поэтому могут выполняться чаще в последовательностях computed reducers.
Если нужен только последний расчёт, используйте прямые source-записи.

`createMethod` теперь делегирует через set, чтобы созданные actions соблюдали
ту же последовательность. Существующий тест конкурирующих async computations
использует прямые записи, продолжая проверять победу последней записи;
reducers в нём теперь намеренно сериализовались бы. `undefined` из computation
по-прежнему означает отсутствие обновления. `null` — настоящее source/output
значение и не заменяется опубликованным значением при сравнении source.

## Async-очередь, ошибки и время жизни

`set` и созданные методы возвращают `void | Promise<void>`. Reducer ожидает,
если нужный output ещё не готов; следующие reducers и прямые записи
попадают в ту же очередь экземпляра. Ожидание записи означает применение
source, а не публикацию финального output. Итог читается через `await get()`.
Вызовы get во время очереди ожидают batch перед чтением.

Reducers должны возвращать синхронные source-значения. Возврат Promise
отклоняется типами и runtime; асинхронные computations поддерживаются.
Отклонение preview, ошибка уже выполняющейся computation и исключение reducer
отклоняют оставшийся batch. Позднейшая независимая запись может восстановить
работу. Обычный get сохраняет прежний fallback последнего значения при ошибке
computation. Игнорируемые Promise записей имеют внутренние обработчики
отклонения; явный await по-прежнему наблюдает ошибку.

`mutate` сохраняет синхронный boolean result. Он отклоняется во время ожидающих
reducer-записей, чтобы незаметно не обходить их порядок. Альтернативы:
асинхронный mutate или постановка mutation в очередь с неверным boolean result.
Сначала дождитесь записи либо выразите обновление reducer. Ожидающее начальное
значение без принятого source также должно разрешиться до синхронной mutation. Неизвестные ключи
объекта, включая ключи из переменных, и неверные scalar/property values
отклоняются compile fixtures.

Disposal и уничтожение через AbortSignal очищают callbacks очереди и previews,
отклоняют ожидающие записи/чтения и инвалидируют идентичность continuation.
Новые wait continuations используют WeakRef; поздние завершения не могут
восстановить уничтоженный сигнал или уведомить подписчиков. Это явная очистка,
а не исправление глобального удержания из [этапа 02](02_LIFECYCLE_RU.md).
Для слабого удержания нужны native weak references; polyfill с сильной ссылкой
не обеспечивает его.

Произвольного ограничения длины очереди нет: потеря принятых записей нарушила бы
порядок. Экземпляр владеет очередью до завершения ожидаемого output или отмены
через явный disposal/abort. Ограничения очереди и независимо отменяемый API
записи можно рассмотреть позже при наличии потребительских примеров.
Тесты используют управляемые Promise и явное уничтожение вместо утверждений
о недетерминированной сборке мусора.

## Проверки и оставшаяся работа

Запустите `pnpm typecheck:signals` или `node _dev/check_signal_types.cjs`.
Команда проверяет строгие source fixtures, генерирует декларации в игнорируемом
`build_cache`, затем проверяет те же положительные/отрицательные контракты
с CommonJS, NodeNext и Bundler resolution. Потребители деклараций используют
skipLibCheck для изоляции использования публичного API; это не сертифицирует
всю сгенерированную библиотеку. Source check сравнивает явный реестр 36
существующих diagnostics, показывает сохранённое количество и записывает
подробности. Добавленные или исчезнувшие diagnostics приводят к ошибке команды
до проверки; обычный `typecheck` всё ещё падает на нерешённой базе библиотеки.

Проверены Node 26.8.1, TypeScript 5.9.3; проходят 103 EventSignal-тестов,
один существующий skip. Полный набор: 386 pass, 14 существующих ошибок
events_spec, один skip, шесть todo. Новых Jest skip или failure нет.
Существующее предупреждение ts-jest 27 о peer версии сохраняется;
runtime-тесты не заменяют строгую проверку типов.

Оставшиеся критерии: дополнительные поддерживаемые версии TypeScript/runtime,
реальные React/SSR-потребители, resolution опубликованного пакета,
исправление lifecycle/global registry и отслеживание зависимостей через
async-границы. До релиза проверьте описанные решения режима результата self, map и mutate
как изменения для миграции.

## Список миграции

- Замените предположение о Promise-only get объявленным union или используйте await.
- Используйте `using signal$ = ...` либо явный disposal принадлежащих вам сигналов.
- Для начальных Promise source по умолчанию — разрешённый payload, а не Promise.
- Предпочитайте полностью выводимые constructor/factory calls; явные async calls
  используют `EventSignal<string, number, undefined, Promise<string>>`.
- Задавайте явный initial/output union, если computation меняет домен значения.
- Все методы self остаются доступны. Если нужен его точный sync/async режим
  результата, аннотируйте callback и все generics через совместимую перегрузку.
- Уничтожайте mapped signals отдельно и удалите записи в односторонние проекции.
- Дождитесь ожидающих reducer-записей перед синхронным mutate.

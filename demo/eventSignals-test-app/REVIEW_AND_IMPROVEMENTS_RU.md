# Лаборатория EventSignal: проверка и улучшения

[English version](REVIEW_AND_IMPROVEMENTS.md) · [Общие рекомендации](../RECOMMENDATIONS_RU.md).

## Назначение и оценка

Приложение может стать полезным интерактивным руководством по writable/computed-сигналам, async-вычислениям, регистрации
компонентов, общему состоянию и жизненному циклу. Проверенные успешные сценарии уже корректно реагируют на изменения, но
для демонстрации потребителям нужны правильная стартовая страница, явные учебные сценарии и единое представление.

Контекст проверки: `dev` / `b943225`, 2026-10-06; Node 26.8.1, существующие зависимости, Vite 5.4.8, React 19.2.4.
Запуск на `http://127.0.0.1:5181`. Замечания с пометкой «статическая проверка» получены из исходников, а не
воспроизведены как ошибки runtime.

## Замечания и рекомендации

### 1. 🟠 Предупреждение — Корневой адрес открывает 404

**Файл:** `demo/eventSignals-test-app/lib/history_navigation.ts`, строки 62–68.

**Проблема:** При открытии `/` первая страница показывает «404 - Not found». Сгенерированные маршруты имеют имена вроде
`/one`; обработчика `/` нет. Посетителю приходится искать навигацию, прежде чем он увидит работающий пример.

```typescript
const newRout = routes.find(routItem => {
  return routItem.routerPath === pagePath;
}) ?? page404route;
```

**Рекомендация:** Добавить обзорную страницу `/` с карточками примеров и описанием демонстрируемых возможностей
EventSignal. Перенаправление на `/one` — допустимый минимальный первый шаг. Неизвестные адреса должны по-прежнему
открывать 404. Приёмка: вход по прямому адресу, перезагрузка и кнопка «Назад» работают для `/` и вложенного маршрута.

### 2. 🟠 Предупреждение — Обычный пример счётчиков начинается с ошибки

**Файл:** `demo/eventSignals-test-app/state/AppStates.ts`, строки 301–308, 336.

**Проблема:** Счётчик начинается с нуля и одновременно задаёт ID пользователя, поэтому первый запрос использует `id=0` и
явно завершается ошибкой. Увеличение счётчика за пределы ID набора данных также разрешено. Для ID 9 специально внесена
ошибка (строки 314–315), но интерфейс не отделяет учебный сценарий от обычной загрузки.

```typescript
const response = await fetch(`https://jsonplaceholder.typicode.com/users?id=${newUserid}`, {
    signal: abortController.signal,
});
// ...
if (!newUserDTO) {
    throw new Error(`User not found with userId=${newUserid}`);
}
// ...
const jsonPlaceholderUser1$ = Object.assign(temp = makePlaceholderUserEventSignal(-1, counter1$), {
```

**Рекомендация:** Выделить выбор пользователя в отдельный сигнал с допустимым начальным ID; счётчик должен независимо
демонстрировать арифметику. Добавить явный переключатель сценариев: успех, задержка, пустой ответ, ошибка и отмена. По
умолчанию использовать локальные данные, а настоящий API включать отдельно. Показывать Retry и состояние запроса.
Приёмка: стандартный пример успешно загружается без сети; ошибки возникают только при выборе соответствующего сценария.

### 3. 🟠 Предупреждение — Кешируемым сигналам нужна модель владения и освобождения

**Файл:** `demo/eventSignals-test-app/state/AppStates.ts`, строки 245–254.

**Проблема:** Кеш хранит сильные ссылки без ограничения размера. Очистка удаляет записи без явного освобождения сигналов
и их незавершённых запросов. Это дополнительный путь удержания объектов наряду с известной проблемой жизненного цикла
регистра EventSignal; рост heap в этой проверке не измерялся. Часть сигналов используется совместно, поэтому безусловное
уничтожение при удалении одной карточки тоже будет ошибкой.

```typescript
const _placeholderUserEventSignalCache: Record<number, ReturnType<typeof _makePlaceholderUserEventSignal>> = Object.create(null);

export function clearPlaceholderUserEventSignalCache() {
    for (const key in _placeholderUserEventSignalCache) {
        delete _placeholderUserEventSignalCache[key];
    }
}
```

**Рекомендация:** Определить владельца кеша, операции acquire/release и вытеснение записей. Отменять незавершённые
запросы и вызывать поддерживаемый API освобождения только после ухода последнего потребителя. Для ресурсов компонента
использовать очистку React effect; `using` подходит для ограниченной синхронной области, а не для срока жизни
отрисованного компонента. Добавить демонстрацию с количеством живых сигналов, подписок и запросов; проверить возврат к
исходным значениям после повторного монтирования/размонтирования и сброса кеша.

### 4. 🟠 Предупреждение — JSON-загрузчик небезопасно сериализует произвольные данные

**Файл:** `demo/eventSignals-test-app/vite.config.ts`, строки 136–146.

**Проблема:** Статическая проверка: JSON встраивается в шаблонную строку генерируемого JavaScript. Обратные кавычки и
`${...}` внутри JSON-строк могут нарушить или изменить получаемый код; ключи вроде `foo-bar` недопустимы как
экспортируемые идентификаторы. Текущие данные собраны успешно, поэтому это дефект обработки входных данных, а не
наблюдавшееся падение текущей сборки.

```typescript
const rawString = JSON.stringify(json);
// ...
const __json = JSON.parse(\`${rawString}\`);
// ...
.map(key => `export const ${key} = __json[${JSON.stringify(key)}];`)
```

**Рекомендация:** Предпочесть стандартное преобразование JSON, если оно удовлетворяет задокументированным требованиям.
Если собственный загрузчик необходим, формировать `JSON.parse` с отдельно JSON-кодированной строкой и экспортировать
только допустимые идентификаторы, сохраняя все ключи в default export. Добавить проверки обратных кавычек, текста
интерполяции, обратных слешей, зарезервированных слов и ключей, не являющихся идентификаторами.

### 5. 🟠 Предупреждение — Пустые клетки игры не имеют доступных имён

**Файл:** `demo/eventSignals-test-app/modules/TicTacToe/TicTacToeGameImmutable.tsx`, строки 43–58.

**Проблема:** До первого хода дерево доступности браузера содержит девять безымянных кнопок. Удаление outline также
убирает явный индикатор фокуса в этой реализации. Ход и возврат к началу игры работают мышью, но навигация клавиатурой и
экранным диктором менее понятна.

```typescript
<button
    style={{ /* ... */ outline: 0, /* ... */ }}
    onClick={onSquareClick}
>
    {value}
</button>
```

**Рекомендация:** Задать каждой клетке имя с номером строки, столбца и текущим значением, сохранить заметный стиль
`:focus-visible` и сообщать смену хода/победителя через ненавязчивую live region. Применить одинаковый контракт ко всем
трём реализациям. Приёмка: пройти игру и её историю только клавиатурой; экранный диктор различает все клетки.

### 6. 🟡 Предложение — Представлению мирового времени нужна компактная иерархия данных

**Файл:** `demo/eventSignals-test-app/pages/10.GlobalTimes.module.css`, строки 473–494.

**Проблема:** Режимы списка и таблицы отображаются, часы обновляются раз в секунду. На проверенной ширине настольного
окна таблица переносит длинные значения и обрезает заголовки, а два заголовка страницы повторяют одно название. Коды
локалей и технические идентификаторы часовых поясов конкурируют с городом и временем.

```css
.cities-container.cities-table {
    font-size: 1.1rem;
    td { padding: 0.3rem; }
    .local-time { font-size: 1.2rem; }
}
```

**Рекомендация:** Сделать город и местное время главными; локаль и IANA-идентификатор перенести в раскрываемые
дополнительные сведения. Обеспечить достаточную ширину заголовков таблицы, выделить контейнер горизонтальной прокрутки и
переходить к карточкам на узких экранах. Добавить поиск городов, избранное, сравнение с часовым поясом пользователя и
ползунок времени встречи. Проверять 390 px и длинные переводы; не объявлять экранному диктору каждый тик часов.

## Направление дизайна

Использовать спокойную общую оболочку и одинаковые карточки примеров вместо отдельного визуального решения для каждой
страницы. Сохранить читаемый системный шрифт, ограниченную палитру и понятные главные/второстепенные действия.
Обозначать активную навигацию не только цветом. Переименовать «Тест два/три/четыре» в демонстрируемые понятия: связанная
форма, async-поиск и общие виджеты.

Для каждого примера дать короткое назначение, ожидаемый результат, сброс и раскрываемое объяснение исходника/API.
Счётчики рендеров, сырые DTO, ключи компонентов и отладочные действия скрыть за переключателем разработчика. Две
реализации поиска размещать рядом на широком экране и вертикально на мобильном, с одинаковым запросом/сценарием для
корректного сравнения. Явно показывать pending, сохранённый предыдущий результат, успешное завершение и ошибку.

В GlobalTimes сохранить полезное региональное форматирование и информацию о часовых поясах, но сделать город/время
главными. Сгруппировать управление и убрать повтор заголовка. Добавить избранное и сравнение времени встречи до
увеличения числа непрерывно анимируемых элементов. Учитывать уменьшение анимации и не объявлять постоянно меняющееся
время.

## Предлагаемый первый пакет реализации

Объединить корневой обзор, корректные данные пользователя и явные сценарии со ссылками на исходники/сбросом. Затем
реализовать владение общим кешем и доступность клеток/клавиатуры. Это даст проверяемую основу до погоды или крупного
изменения дизайна. Общие рекомендации задают работы по среде, копиям библиотеки и проверкам.
